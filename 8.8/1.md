# 数据库

## SQL 优化

SQL 优化核心目标：减少扫描行数、减少回表、减少临时表与文件排序，降低 IO 开销

- 索引：B+树 3~4 叶子节点 双向链表，Hash
    - 自动：主键、外键、唯一约束
    - 手动：where、join、order by、group by
    - 避免了全表扫描、回表问题
    - 索引不是越多越好：索引加快查询，但降低 insert/update/delete 写入性能，索引会占用磁盘空间。
- 优化SQL语句 核心思想：尽量让 MySQL 少扫描数据、少排序、少生成临时表，充分用上索引，减少 IO。
    - 禁用 SELECT*
    - 少用or，可以用union all改写；union会去重产生临时表，优先union all。
    - group by尽量利用索引有序性，避免Using temporary。
    - join 多表：小表驱动大表，join 字段建立索引，控制 join 表数量，不建议超过 3 张表。
    - 避免在 where 子句做运算、函数
    - 尽量用exists代替大表in；in 集合不要过大
- 执行计划
- 分表
    - 表分区：数值范围、值
- 分库

## 进程

进程：是具有独立功能的程序在一个数据集合上的一次运行过程，是系统资源分配的基本单位。
线程：进程内的执行流，是CPU 调度（处理机调度）的基本单位。

### 多线程
- fork 创建一个子进程
- exec  
- getpid    进程id
- getppid   父进程id
